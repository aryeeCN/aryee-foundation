# ADR-003: BOM 分层依赖版本管理

## 状态
✅ 已采纳

## 背景
大型多模块项目的依赖版本管理是一个核心挑战。需要确保所有模块使用一致的第三方依赖版本，同时支持业务项目按需引入，避免全量依赖污染。

## 决策
采用 **BOM 分层设计**，共 4 类 BOM：

| BOM 模块 | 作用 | 适用场景 |
|---|---|---|
| `bom-base` | 管理所有第三方依赖版本 | 所有 BOM 的根基，不直接被业务模块 import |
| `bom-{module}` | 按功能聚合的 BOM | 业务项目按需引入 |
| `bom-internal` | 管理所有内部模块版本 | 多模块业务项目引入 |
| `bom-full` | 合并 bom-base + bom-internal | 对外发布、全量引入 |

## 核心原则
- **版本唯一来源**：所有依赖版本号只在 `bom-base` 的 `<properties>` 和 `<dependencyManagement>` 中定义
- **子模块零版本号**：各子模块依赖声明省略 `<version>`，版本由父 POM + BOM 传递
- **父子两层继承**：功能聚合 POM 继承技术父 POM，子模块继承功能聚合 POM
- **SPO 单一指向**：新增第三方依赖必须先在 `bom-base` 声明

## 影响
- 版本升级只需修改一处（`bom-base`），全项目生效
- 业务项目可以按需引入 BOM，避免传递不必要的依赖
- 有效避免版本冲突和依赖地狱
